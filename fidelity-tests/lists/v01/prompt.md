# gdt-lists-v01 — prompt

I'm testing a CLI against this doc, so build a document that uses a bunch of the
formatting and functionality available in Google Docs for **lists**, the way a real
internal doc looks after several people have pasted into it for months. Use browser
control and pick things you think will be hard to replicate for a tool connected through
the Docs API. Make it messy rather than a feature demo: combine at least two of these in
most paragraphs.

- three separate numbered lists that look like one continuous list (a plain paragraph
  between them, one continued with "Continue previous numbering", one restarted at 1)
- a numbered list that turns into a checklist halfway, with some items ticked
- manual "1)" / "a." numbering typed as text next to and inside a real list
- nested bullets three levels deep with mixed glyphs (●, ○, ■, then a dash typed by hand)
- a bulleted list where one item is a heading style and one is bold 14pt Normal that
  looks like a heading
- list items containing emoji and non-Latin text (Japanese, Cyrillic, Spanish accents)
- a list interrupted by an indented plain paragraph that looks like a list item
- a list item with a soft line break (shift+Return) inside it
- the same phrase appearing in two different lists and once outside any list, with
  different formatting (bold, linked, plain)
- a list pasted from Word or Slack with fonts and sizes still attached
- a comment anchored across two list items; a pending suggestion that changes one item
- empty list items, trailing spaces, tab characters after the glyph text
- anything else about lists you find hard to do

Two to three pages is plenty. Write real-sounding content (an onboarding checklist, a
release plan, meeting action items), not lorem ipsum.
