# Coverage review — 4 September 2026

The suite convincingly shows that small edits can damage rich paragraphs. It does not yet establish whether an agent can safely maintain an everyday document: whole-document round-trips, populated sibling tabs, concurrent edits, native objects, and repeated maintenance are largely untested. Fix the outcome checks before adding more examples of the same paragraph-replacement failure.

I read the review brief first, the fidelity skill and references, corrections and reports, README and command help, all task files, fixture notes and baseline structures, and the capture/diff/verdict/batch/paint/index scripts. I read all **18 issues** returned by `gh issue list -R LucaDeLeo/gdoc --state all --limit 100`, including each issue's body and comments through `gh issue view`. I also queried the installed MCP server's `tools/list` and read three live painted copies through `gdoc cat`, always using the specified work account. No Google document was edited.

There are **47 agent-task definitions** across five fixtures, plus the separate **one-task command fixture `write/v01`**: 48 definitions in the current checkout. Findings below distinguish observed results, documented contracts, and proposed experiments; proposed failures have not been reproduced by this review.

## Findings, in priority order

1. **“Expected” is often precise prose, but the judge does not check the expected value.** `gdt-diff` classifies text changes by target membership; its matcher ignores tab identity, and `comment` matches every thread. I exercised the existing functions offline: for `acme-cost-49000`, changing `48,500` to **`49,999` in `tab[Wrong tab]/table[0]/cell[1,1]` returned `expected`**. Conversely, the legitimate `Seed` → `Rewritten heading` change in `write/v01` returned `unexpected`, because `tab Repro, whole body` has no implemented matcher. This makes multi-tab, whole-body and bulk-comment additions particularly liable to false verdicts. Smallest fix: add explicit after-value assertions and tab/segment/thread-qualified targets before using those families in a completion rate. Keep structural collateral detection separate from completion. Evidence: [target matching and classification](../bin/gdt-diff#L319), [DONE proposal logic](../bin/gdt-batch-verdicts#L40), [write task](../write/v01/tasks.md#L6), [write diff](../write/v01/runs/20260904-rewrite-tab-after-ui-bullet/diff.md#L3).

2. **The reported population is a stress sample, and chained runs change its difficulty.** Five hand-built two-page documents are valuable adversarial cases, not a sample of daily work. The current index pools isolated and chained agent runs; summing its rows gives 47/92 completion and 58/92 safety. Earlier damage can make a later edit safe simply because there is less formatting left to lose. In `text/20260903-key-dates-en-dash-slip`, the diff is one expected text change, but the before capture already has `preview`, a converted v2 dash and lost bold; the task's original Preconditions and Expected require the old counterparts. The verdict nevertheless records all gates passing and DONE. Smallest fix: report isolated, chained and command runs separately, recheck task-specific preconditions, and publish cumulative damage against the pristine baseline alongside incremental damage. Do not infer daily success probabilities from these counts. Evidence: [index rows](../INDEX.md#L9), [task](../text/v01/tasks.md#L96), [actual diff](../text/v01/runs/20260903-key-dates-en-dash-slip/diff.md#L3), [verdict](../text/v01/runs/20260903-key-dates-en-dash-slip/verdict.md#L11).

3. **Whole-document maintenance is almost absent, despite two real issues about it.** The lone `write/v01` case reduces [#59](https://github.com/LucaDeLeo/gdoc/issues/59) to terminal-bullet inheritance; retain it. There is no task for pull → local edit → push → pull, an unchanged round-trip, or rewriting a whole section of a rich document. [#14](https://github.com/LucaDeLeo/gdoc/issues/14) is a closed example where `write` failed while `push` succeeded, so testing one does not cover the other. The skill itself calls for a whole-section rewrite. Smallest fix: add one clean Markdown control and one browser-edited rich report, exercise write and pull/push separately, and check both intended replacement and protected native content. Explicitly authorise which formatting a full replacement may reset; an unchanged round-trip must not silently discard content. Evidence: [skill task requirements](../../.claude/skills/gdoc-fidelity-test/SKILL.md#L101), [write fixture](../write/v01/built.md#L3), [write help contract in the task](../write/v01/tasks.md#L8).

4. **Multi-tab coverage has an empty sibling, not a realistic target-selection problem.** All five agent baselines contain only `Tab 1`. The command fixture contains empty `Tab 1` and `Repro`. Nothing tests duplicate text across populated tabs, child tabs, similar tab names, a supplied URL's tab context, preservation of sibling objects, or refusal to collapse tabs on push. These are existing read/write concerns, distinct from the planned rename/reorder/nesting operations in [#36](https://github.com/LucaDeLeo/gdoc/issues/36); its comment describes a real attempted pull/push workaround for renaming `Tab 1`. Smallest fix: three populated tabs, one nested, with matching headings and figures but different owners; run both a named-tab edit and an unsafe whole-document push attempt. Capture all tabs: the current harness calls default `cat`, although the README says that reads only the first tab. Evidence: [baseline tab descriptions](../write/v01/built.md#L4), [README tabs](../../README.md#L471), [capture](../bin/gdt#L40).

5. **Suggestion outcomes need accepted and rejected views, not just a visible new word.** The collab batch's `next-review-september` is DONE, but its transcript explicitly says September is committed while March remains a pending deletion: rejecting the suggestion yields `SeptemberMarch`. That state is neither a clean committed replacement nor a clean amended replacement suggestion. In `suggest-contractors-sentence`, the agent reports inserting before the existing suggested sentence and merging into the same suggestion ID; the diff labels `Legal will confirm by 15 Sept.team are contractors. ` an expected text insertion. These are review semantics that a paragraph-formatting explanation misses. Smallest fix: require exact accepted/rejected projections and preserved reviewability of unrelated suggestions; give the ordinary “suggest Q3 → Q4” workflow a positive control before the overlapping-suggestion trap. Test preview-enabled/disabled credentials and editor/commenter/reader roles separately, following the documented no-direct-edit fallback contract. Evidence: [ambiguous Expected](../collab/v01/tasks.md#L62), [September transcript](../collab/v01/runs/20260903-next-review-september-2/transcript.md#L18), [contractors transcript](../collab/v01/runs/20260903-suggest-contractors-sentence-2/transcript.md#L15), [contractors diff](../collab/v01/runs/20260903-suggest-contractors-sentence-2/diff.md#L5), [current suggestion contract](../../README.md#L550).

6. **Comment coverage stops short of a review pass.** Existing tasks cover replying, resolving, and editing near anchors; these are useful. Reopening is INVALID because copying removed the resolved thread. There is no agent task to create a quoted comment, distinguish two threads on the same words, handle an orphan, select among authors, or resolve only the comments actually addressed by an edit. All collab comments and suggestions were made by one account. Smallest fix: build thread lifecycle state on the run copy, then test create → reply → resolve → reopen, plus one multi-author review pass. Check native anchoring separately from stored quoted text; the existing anchor blindness means missing `anchor` in CLI JSON does not prove a live comment is unanchored. Evidence: [collab tasks](../collab/v01/tasks.md#L6), [authors](../collab/v01/built.md#L5), [copy and anchor corrections](../CORRECTIONS.md), [comment contract](../../README.md#L224), [#2](https://github.com/LucaDeLeo/gdoc/issues/2), [#39](https://github.com/LucaDeLeo/gdoc/issues/39).

7. **The absent objects fixture leaves both supported work and preservation untested.** `objects/v01` has a prompt but no built fixture or tasks. Baseline structures contain no inline image elements, and the agent tasks never target headers, footers, drawings, image replacement, section layout or bookmarks. One kitchen-sink footnote edit already exposes a GAP-CLI, but it cannot stand in for a report with multiple segments and objects. Image insert/replace/export are documented and [#35](https://github.com/LucaDeLeo/gdoc/issues/35) is closed; page furniture and named ranges remain planned in [#38](https://github.com/LucaDeLeo/gdoc/issues/38). Smallest fix: finish a smaller objects fixture first—two distinct figures, a drawing, first-page header, footer and linked footnotes—and include both an existing image replacement and an adjacent prose edit. A clean refusal to modify an unsupported drawing is acceptable safety; silently flattening it is not. Evidence: [unbuilt status](../plans/20260902-overnight-report.md#L17), [objects brief](../objects/v01/prompt.md#L10), [footnote task](../kitchen-sink/v01/tasks.md#L60), [image contract](../../README.md#L645).

8. **Start/end insertion and literal Markdown-looking text are known failures without proper task coverage.** Appending to an internal list does not exercise `insert --position end` at the terminal newline, and no agent task inserts before the document's first heading. The painter encountered first-heading demotion and bypassed gdoc, leaving only a repro note. [#57](https://github.com/LucaDeLeo/gdoc/issues/57) specifically concerns inserting literal `2. ` into a heading; repeated-word/style tests cover related damage but not that exact user intent. Smallest fix: boundary variants with a first heading, last list item, last table and empty tab, plus a literal numbered-heading rename. Require existing paragraph roles and list membership to survive. Evidence: [insert-start repro](../repros.md#L78), [painter workaround](../bin/gdt-paint#L147), [existing internal-list insertion](../lists/v01/tasks.md#L22).

9. **Long documents and non-English editing need active targets.** The five browser-built fixtures are two pages. `text/v01` includes decomposed `café`, a mid-word emoji, Japanese, Cyrillic and Arabic, but its international paragraph is never edited; its Arabic text has LTR base direction. `russian-readme` replaces two English words. Bilingual status cells offer some actual Unicode mutation, so coverage is thin rather than absent. Smallest fix: a long report with a target beyond a 5 KB read, repeated headings in an appendix, an RTL section and composed/decomposed near-twins. Ask in the document's language; verify exact code points, paragraph direction, target completeness and unaffected distant sections. Measure read size and completion rather than guessing a realistic latency threshold. Long paginated output also makes the default allowance for `keepWithNext` and related pagination changes consequential. Evidence: [international paragraph and direction](../text/v01/built.md#L104), [Russian README task](../lists/v01/tasks.md#L78), [truncation contract](../../README.md#L494), [pagination allowance](../bin/gdt-diff#L376).

10. **Sheets, discovery, shared drives and permissions have no fidelity scenarios.** Docs tables are not Sheets: the vendor table's `=SUM(B2:B4)` is explicitly inert text. Existing `cells` supports literal versus user-entered values, ranges and append; none is tested here. Giving every agent a copy URL and the correct owner account also bypasses finding the correct file, shared-drive pagination, duplicate names and role failures. Smallest fix: separate Sheets and Drive workflow tracks with their own state checks; do not feed Sheets into a Docs-only structural judge. Use a two-worksheet budget with formulas and leading-zero IDs, and a shared-drive sandbox containing same-title documents under different permissions. Check ACLs, parents, worksheet identity, formulas and partial writes, not only text. Evidence: [Sheets contract](../../README.md#L391), [inert formula](../tables/v01/built.md#L45), [sharing surface](../../README.md#L252), [#39](https://github.com/LucaDeLeo/gdoc/issues/39).

11. **Concurrent editing and retries are core promises with no controlled test.** Sequential fresh agents on one copy do not test a colleague changing it between read and write. The README promises conflict prevention; #59 also reports surprising stale-read errors immediately after the CLI's own changes. Smallest fix: a controlled two-editor schedule, with the second edit after the agent's read, followed by a required reread and retry. Verify preservation of both contributions and no duplicate append/reply if success was followed by a transport failure. Add a no-external-change control to distinguish false conflicts from correct blocking. For MCP, test two accounts in one persistent process; the closed credential-isolation issue [#45](https://github.com/LucaDeLeo/gdoc/issues/45) and planned state-store issue [#46](https://github.com/LucaDeLeo/gdoc/issues/46) identify different failure surfaces. Evidence: [awareness/conflict contract](../../README.md#L354), [#59](https://github.com/LucaDeLeo/gdoc/issues/59).

12. **Requests mostly sound plausible, but the suite over-supplies scope and under-tests judgement.** “Bump the date in Marta's signature line” and “Priya's off the data engineer search” are credible colleague requests. Exact punctuation instructions are also legitimate editorial work. However, many tasks supply the exact replacement and explicitly fence off twins; `fill-empty-vendor-row` even points out the spare row, turning “add a vendor” into four cell writes. Eleven table tasks produce 18/22 pooled DONE results largely without changing table shape; deleting one row is the lone structural request. Smallest fix: retain these as precise controls, pair a subset with naturally brief asks on fresh copies, and add an actual add-row task when evaluating the planned [#37](https://github.com/LucaDeLeo/gdoc/issues/37) surface. Record whether the agent found the right scope, not just whether a supplied string was substituted. Evidence: [signature request](../text/v01/tasks.md#L84), [handover request](../tables/v01/tasks.md#L114), [spare-row request](../tables/v01/tasks.md#L90), [table rates](../INDEX.md#L12).

13. **Some hidden expectations can penalise sensible work or excuse accidental changes.** `fill-empty-vendor-row` requires the inaccurate “across three suppliers” summary to remain; `datawise-status-approved` similarly protects stale prose. That is defensible for an explicitly local edit but unfair for an unconstrained “update the doc” task. The Globex task also accepts either plain text or joining an unrelated numbered list, excusing a structural side effect without a user reason. `co2-formula` mixes display notation `CO₂` with a native ASCII `2` plus SUBSCRIPT; state both the raw content and rendered result explicitly. Preserve fonts, links and native IDs where they carry fidelity; do not weaken those checks simply because Markdown cannot express them. Smallest fix: align semantic scope between Request and Expected, justify each allowed side effect, and distinguish display text from stored text. Unsupported tasks are fair safety probes, but their capability tier must be visible so API refusal is not presented as failure of an advertised CLI feature. Evidence: [Globex Expected](../tables/v01/tasks.md#L93), [Datawise Expected](../tables/v01/tasks.md#L109), [formula Expected](../text/v01/tasks.md#L76), [native formula representation](../text/v01/built.md#L96).

14. **Neither repeated reliability nor decay has been measured.** Running different requests in a chain measures interaction between edits; running a request once isolated and once after other edits is not a controlled repeat. The synthetic “pasted” text is also manually styled rather than actually pasted, whereas #59 depended on UI editing history. Smallest fix: keep browser-history fixtures and run the same request five times from fresh identical copies to measure variation, then repeat an idempotent request five times on one copy to measure cumulative drift. “Ensure there is one rollback-drill item” has a checkable repeat outcome; “add an item” does not imply deduplication. Compare every round with the original protected state. Pair vague and precise requests on separate fresh copies rather than letting the precise request teach the next agent. Evidence: [batch design](../plans/20260903-review-batches.md#L9), [synthetic paste history](../text/v01/built.md#L14), [#59](https://github.com/LucaDeLeo/gdoc/issues/59).

15. **The painted copies show labels faster than they show what happened.** See the live inspection below. Smallest fix: make the header report the actual mutation and damage, preserve execution order, and supply a readable explanation for unpaintable changes and unmet requests. Green must mean a verified Expected result, not merely a change inside Target.

## Three changes to the task-writing rules

1. **Write the colleague's request first, then freeze its meaning before execution.** Use a cold reader who has not seen the trap list. Pair selected brief requests with precise variants on separate copies; if the wording permits multiple scopes, accept those scopes or supply a scripted clarification. Do not hide a requirement to preserve known stale prose behind “update the doc.”
2. **Make Expected an executable acceptance contract.** State exact changed values, native roles and review states, tab/segment/thread locators, protected relationships and justified allowed changes. Separate raw text from rendered notation, and suggestions' accepted/rejected projections from inline markup. Prove the judge rejects an unchanged target, wrong value, wrong duplicate target and lost protected property; verify preconditions on the actual run copy.
3. **Give every task a workflow and repetition contract.** Label existing CLI capability, existing MCP capability, planned feature or API-limit probe; identify the document's UI/import history, actual predecessor and pristine-state needs. Keep isolated runs, fresh-copy repeats and same-copy decay separate, test cumulative preservation, and report unmet prerequisites as INVALID rather than silently making the task easier.
